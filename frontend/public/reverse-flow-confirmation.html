正向与逆向流程确认问题

本页用于确认正向节点、基础回退边界、出库前取消、出库后退货退款，以及第一版财务处理模型。 核心口径：入库单创建后产生供应商应付，客户应收仍在确认出库时产生；逆向单据边界由是否涉及钱决定， 出库边界由原正向履约单据是否还允许被关闭/取消决定。

业务单据 钱 / 财务 货 / 库存 履约终止

一、先确认两个边界不要混用

核心口径
边界一：财务事实边界

如果正向改成“创建入库单 = 确认供应商发货/我方拉货 = 产生供应商应付”， 那从这个点开始，后续任何取消/退货/退款只要涉及钱，都必须有逆向申请或逆向财务单据承载。 客户预收可以在销售单后独立存在，但不驱动履约节点；客户应收仍在确认出库时产生。

边界二：履约终止边界

出库单形成/装柜出库的意义不是“从这里才开始需要逆向单据”，而是原正向履约链路到这里终止。 出库后逆向只能关联原单据，不能把原销售、采购、入库、出库单倒回取消。

二、建议确认后的三段式逆向阶段

阶段划分
发货/拉货确认前 履约单据回滚，预收另行处理
→
入库单创建后，出库单形成前 已有供应商应付，可关闭原履约链
→
出库单形成后 售后逆向，原正向单据不回滚

三、正向流程口径

正向草案

目标是把应付前移到入库单创建，应收保持在确认出库。

  • 1. 入库单创建是否等同于确认供应商发货/我方拉货？ 如果是，入库单创建就不再只是登记在途，而是外部履约事实发生。
  • 2. 入库单创建时只产生供应商应付，客户应收仍在确认出库时产生。 应付从确认入库前移到创建入库单；应收不前移。
  • 3. 客户预收不作为正向流程节点，只作为后续应收核销对象。 销售单成立后可以有客户预收；确认出库产生应收后，再用收款单或既有预收核销。

四、基础回退需要确认

纯状态回滚

基础回退只讨论“不涉及供应商应付、不涉及外部发货事实”的履约单据范围；客户预收如已发生，按独立财务事项处理。

  • 1. 纯状态回滚是否只允许到发货/拉货确认前？ 建议口径：报价、销售、采购阶段，如果供应商未动货，可以逐级取消或作废。
  • 2. 一旦创建入库单并产生供应商应付，是否就不再允许裸状态回滚？ 建议口径：只要涉及应付、预付、预收退回、退款等钱的处理，就必须有逆向申请或逆向财务单据。
  • 3. 当前平台已有的单据取消状态是否够用，还是需要新增“履约中取消”状态？ 现状是销售、采购、入库、出库各自有取消状态，但没有统一逆向申请承载整条链路。

五、出库边界需要确认

履约终止边界

出库边界要确认的是：逆向处理后，原正向单据还能不能被改成取消/关闭/退回完成。

  • 1. “出库单形成”具体指创建出库单 DRAFT，还是确认出库 ISSUED？ 建议第一版谨慎确认。如果业务上说“货装进柜/出库”，系统上更接近 ISSUED；如果只要建出库单就锁原流程，也要明确。
  • 2. 出库前取消完成后，原销售单、采购单、入库单是否允许进入取消/关闭/退回完成？ 这是出库前取消和出库后售后的本质区别。
  • 3. 出库后退货退款是否只能新增售后逆向链路，原正向单据保持原状态？ 建议口径：原销售、采购、入库、出库单只作为历史依据被关联，不再倒回。
  • 4. 已装柜未封柜、已封柜、已离港、客户已收货，是否都是出库后售后流程的子状态？ 建议第一版不作为主流程边界，只影响审批层级、费用和附件要求。

六、MVP 逆向入口一：出库前取消

履约中取消

适用：入库单创建后、出库单形成前。已经涉及供应商应付，所以必须有逆向单据。

  • 1. 是否新建“出库前取消/履约中取消申请单”？ 建议关联销售单、采购单、入库单，并记录供应商确认结果。
  • 2. 货未到货代仓和货已到货代仓是否共用一个流程？ 建议共用；差异只在货已入仓时多处理销售单维度库存。
  • 3. 供应商接受时，是否生成供应商退货单或在途取消单？ 未到仓：在途拦截/退回；已到仓：从销售单库存扣减并退供应商。
  • 4. 供应商不接受时，公司不承担是否直接驳回客户取消？ 如果驳回，原履约链继续，原供应商应付继续存在；客户侧如有预收，按是否同意退款另行处理。
  • 5. 供应商不接受但公司承担时，是否生成费用/损失并处理客户预收退回或退款？ 供应商侧不退钱，应付不冲正；出库前通常未产生客户应收，客户侧主要处理预收退回或退款。

七、MVP 逆向入口二：出库后退货退款

售后逆向

适用：出库单形成后。原正向单据不回滚，只新增售后逆向流程。

  • 1. 是否新建“客户退货退款申请单”？ 建议关联销售单和出库单，并追溯入库单、采购单。
  • 2. 供应商接受时，生成供应商退货单、换货单，还是第一版只做退货？ 建议 MVP 先支持退货退款主线，换货/补货作为后续扩展。
  • 3. 供应商不接受但公司承担时，是否按费用/赔付处理？ 客户侧退款或应收冲销；供应商侧采购成本不冲正。
  • 4. 客户退回货是否默认不进入自由库存？ 建议第一版明确不进自由库存，按退供应商/换货/待处置处理。
  • 5. 出库后不同物流状态是否只影响审批和费用？ 已装柜未封柜、已封柜、已离港、客户已收货，不建议第一版拆成不同主流程。

八、MVP 财务处理模型

先走通一条

第一版不要把预收、预付、自动反核销、贷项通知、红字发票全部做满。建议按出库前/出库后分开： 出库前重点处理预收退回和供应商应付冲销，出库后再处理客户应收冲销和退款。

客户侧
  • 出库前未产生应收：已收款则做退款/预收退回，未收款则不做应收冲销。
  • 出库后已产生应收：未付款则生成应收冲销单。
  • 出库后已付款或部分付款：已付部分退款，未付部分冲销。
供应商侧
  • 供应商接受且未付款：生成应付冲销单。
  • 供应商接受且已付款：生成供应商退款单。
  • 供应商不接受：应付不冲正，已付款作为采购成本保留。
  • 1. 第一版是否确认客户侧按阶段处理：出库前预收退回/退款，出库后退款单 + 应收冲销？ 这样可以保留“客户预收不驱动流程节点”的口径，同时保证钱有单据承载。
  • 2. 第一版是否确认使用“供应商退款单 + 应付冲销”作为供应商侧主模型？ 供应商不退钱时不做供应商侧冲销，由公司承担差额。
  • 3. 公司承担金额是否先落“费用/损失”口径？ 后续可再细分赔付、质量损失、运费损失、坏账等科目。

九、第一版开发范围建议

最小可行单元
先做
  • 正向：入库单创建时产生供应商应付；确认出库时产生客户应收。
  • 基础回退：发货/拉货确认前的纯状态回滚。
  • 逆向入口一：出库前取消/履约中取消。
  • 逆向入口二：出库后客户退货退款。
  • 财务：退款单/供应商退款单 + 应收应付冲销 + 公司费用/损失。
后做
  • 自动匹配预收、预付。
  • 复杂反核销和多单分摊。
  • 换货、补货、多级质量责任。
  • 贷项通知、红字发票完整模型。
  • 复杂审批流和金额阈值升级。
