# 出库后异常受控处理方案

> 适用阶段:0811 基础回退收紧后,0812 退货退款/冲正单据上线前。

## 背景

出库单确认为 `ISSUED` 后,系统将其视为正向履约事实终点。原出库单不再允许撤销回 `DRAFT`,也不再通过原链路恢复库存或作废应收。

当前系统尚未实现客户退货单、供应商退货单、客户贷项单、退款/费用单等线上逆向单据。因此出库后的异常不能引导业务用户自行新建线上逆向流程。

## 当前处理原则

1. 业务页面只提示“当前系统暂不支持出库后线上冲正,请联系管理员处理”。
2. 普通用户不可通过前端或公开 API 撤销已出库单。
3. 管理员处理前必须确认异常类型、影响单据、库存影响、应收/收款影响和审批授权。
4. 管理员处理必须留痕,包括申请人、审批人、处理原因、受影响单据、处理前后金额/数量和附件。
5. 如异常涉及客户退款、供应商退款、费用承担或库存实物流向,财务和业务负责人必须共同确认。

## 受控处理清单

管理员接到出库后异常时,至少完成以下检查:

1. 确认出库单、销售单、采购单、入库单、发运柜和相关财务单据。
2. 判断是否已经存在收款/付款核销、报关、物流轨迹、到港或其他外部事实。
3. 判断异常类型:
   - 操作误点确认出库。
   - 出库数量或商品录错。
   - 实际未发货但系统已确认。
   - 客户退货。
   - 需要冲减应收或恢复库存。
4. 判断是否允许在系统外处理:
   - 若仅是展示/备注问题,优先通过备注、附件或后续单据记录。
   - 若涉及金额、库存或客户/供应商权益,必须由负责人审批。
5. 形成处理记录,并在 0812 模块上线后补录或迁移为正式逆向单据。

## 后续线上化方向

0812 应以独立逆向单据承载出库后事实,而不是恢复 `ISSUED -> DRAFT`:

1. 客户退货单:确认退货商品、价格、数量、原因和客户诉求。
2. 供应商退货单:确认供应商是否接受退货及实物流向。
3. 客户贷项/退款/费用单:承载客户侧金额冲减或退款。
4. 供应商借项/退款/预付冲正单:承载供应商侧金额冲正。
5. 审批任务:按具体用户指派处理人,角色只作为资格门槛。
